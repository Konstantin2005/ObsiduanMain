
Сокет — это программная конечная точка для обмена данными между процессами. В Linux сокеты используются для сети (TCP/UDP) и для локального IPC (Unix‑сокеты).

---

## Виды сокетов

### Network socket

- Использует IP + порт.
- Пример: `0.0.0.0:80`, `127.0.0.1:5432`.
- Протоколы: TCP, UDP.

### Unix socket

- Использует путь к файлу, например `/run/docker.sock`.
- Быстрее, чем TCP на localhost.
- Удобен для локального взаимодействия сервисов.

---

## Где это видно

```bash
ss -ltnp
ss -lxnp
```

- `-ltnp` — слушающие TCP‑сокеты.
- `-lxnp` — Unix‑сокеты.

---

## Примеры

- Nginx слушает `0.0.0.0:80` — TCP‑сокет.
- Docker API доступен через `/run/docker.sock` — Unix‑сокет.

---

## On-call диагностика сокетов

Посмотреть сокеты процесса:
```bash
ss -ltnup
ss -lxnp
lsof -p <pid> | rg socket
```

Частые симптомы:
- `bind: address already in use` -> порт занят другим процессом;
- `too many open files` -> исчерпаны file descriptors;
- не создается unix-socket файл -> права/путь/SELinux/AppArmor.

---

## Типовые ошибки

- Оставили unix-socket с широкими правами (`chmod 777`).
- Нет ротации/перезапуска при «подвисших» unix-сокетах.
- Неправильная интерпретация: проблема приложения, а не сети, если это unix-socket.

---

## Собес фокус

- Разница между TCP socket и Unix socket.
- Как связаны socket и file descriptor в Linux.
- Почему `ss` обычно лучше `netstat` для диагностики.
