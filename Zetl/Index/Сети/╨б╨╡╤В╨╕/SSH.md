
SSH (Secure Shell) — защищённый протокол удалённого доступа к системе и безопасного обмена данными. Работает поверх TCP (обычно порт 22).

---

## Что даёт SSH

- Шифрование трафика.
- Аутентификация пользователя/сервера.
- Безопасные удалённые команды и туннели.

---

## Типовые возможности

- Вход на сервер: `ssh user@host`.
- Копирование файлов: `scp`, `sftp`.
- Туннели (port forwarding): `-L`, `-R`, `-D`.

---

## Как работает (кратко)

1. Клиент подключается по TCP к серверу (обычно порт 22).
2. Сервер отправляет свой публичный ключ (host key).
3. Клиент сверяет ключ сервера (файл `~/.ssh/known_hosts`).
4. Дальше идёт аутентификация пользователя (пароль, ключи, либо другие методы).
5. После успешной аутентификации трафик шифруется и идёт по защищённому каналу.

---

## Аутентификация

- **Пароль** — проще, но менее безопасно.
- **Ключи** — безопаснее и удобнее для автоматизации.
  - Публичный ключ хранится на сервере (`~/.ssh/authorized_keys`).
  - Закрытый ключ остаётся у клиента и никогда не покидает его.

---

## Быстрые команды

```bash
ssh user@server
ssh -i ~/.ssh/id_rsa user@server
ssh -L 8080:localhost:80 user@server
```

---

## Безопасная практика

- Отключить логин по паролю и оставить только ключи.
- Ограничить доступ по `AllowUsers`/`AllowGroups` в `sshd_config`.
- Использовать `fail2ban` или rate‑limit для защиты от перебора.

Базовые параметры `sshd_config`:
```conf
PermitRootLogin no
PasswordAuthentication no
PubkeyAuthentication yes
AllowUsers devops deploy
MaxAuthTries 3
```

## On-call диагностика SSH

Сервер недоступен по SSH:
```bash
nc -zv <host> 22
ssh -vvv user@host
ss -ltnp | rg ':22'
journalctl -u sshd -n 100 --no-pager
```

Что проверять:
- доступность порта и маршрут;
- firewall/security group;
- права на `~/.ssh` и `authorized_keys`;
- mismatch host key (`known_hosts`).

---

## Типовые ошибки

- Неверные права на каталог/ключи пользователя.
- Ротация host key без обновления known_hosts у клиентов.
- Доступ только по ключу включили, но ключи не разложили.
- Открытый SSH в интернет без ограничений по IP/2FA/bastion.
