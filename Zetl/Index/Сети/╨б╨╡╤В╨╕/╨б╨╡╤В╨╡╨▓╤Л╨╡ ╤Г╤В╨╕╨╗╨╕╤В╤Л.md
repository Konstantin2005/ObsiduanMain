
Ниже краткие примеры использования базовых сетевых инструментов и тех, что чаще всего нужны в DevOps.

---

## ping

Проверка доступности хоста и задержки.

```bash
ping 8.8.8.8
ping -c 4 example.com
```

Полезно для быстрой проверки “жив ли хост” и оценки RTT. Если `ping` не проходит, это не всегда значит, что хост недоступен — ICMP может быть заблокирован.

Важно: `ping` работает по **ICMP**, у него **нет TCP/UDP порта** (IP protocol 1).

---

## traceroute

Путь до узла с промежуточными hop.

```bash
traceroute example.com
traceroute -I 8.8.8.8
```

Показывает, на каком участке маршрута возникают потери/задержки. `-I` использует ICMP вместо UDP.

**Как работает:**

- Отправляет пакеты с TTL=1, затем TTL=2, 3, …
- Каждый маршрутизатор уменьшает TTL на 1.
- Когда TTL становится 0, роутер возвращает ICMP Time Exceeded.
- По этим ответам строится список hop.

## telnet

Проверка TCP‑порта и простое взаимодействие с текстовыми протоколами.

```bash
telnet example.com 80
```

Используется для проверки доступности порта и “ручных” запросов. Для защищённых протоколов лучше `openssl s_client` или `curl`.

---

## netstat

Список соединений и портов (устаревшая, но встречается).

```bash
netstat -tulpen
netstat -an | grep LISTEN
```

Показывает слушающие порты, соединения и PID процесса. В новых системах заменяется на `ss`.

---

## netcat (nc)

Универсальный инструмент для TCP/UDP.

```bash
# Проверка порта
nc -zv example.com 443

# Простой TCP сервер
nc -l 9000

# Отправка данных
echo "hello" | nc 127.0.0.1 9000
```

Используется для проверок портов, простых тестов, “ручных” соединений и отладки.

---

## route

Старый инструмент для маршрутизации.

```bash
route -n
route add default gw 192.168.1.1
```

Показывает таблицу маршрутов. В новых системах заменяется на `ip r`.

---

## ip

Современная замена `ifconfig` и `route`.

```bash
ip a
ip r
ip link set eth0 up
ip addr add 192.168.1.10/24 dev eth0
```

Основной инструмент для работы с интерфейсами, адресами и маршрутами.

---

## ifconfig

Устаревший инструмент для интерфейсов.

```bash
ifconfig
ifconfig eth0 up
ifconfig eth0 192.168.1.10 netmask 255.255.255.0
```

Может отсутствовать по умолчанию. Используется в старых системах.

---

## nslookup

Проверка DNS‑разрешения.

```bash
nslookup example.com
nslookup example.com 8.8.8.8
```

Быстро показывает, какой IP возвращает DNS и какой сервер отвечает.

---

## ss

Современная замена `netstat` для сокетов.

```bash
ss -tulpen
ss -tan state established
ss -ltnp | grep 443
```

Быстрее и информативнее, удобен для поиска слушающих портов и активных соединений.

---

## dig

Более точный DNS‑клиент, чем `nslookup`.

```bash
dig example.com
dig A example.com
dig example.com @8.8.8.8
```

Показывает полные ответы DNS и удобно используется для отладки записей.

---

## curl

Проверка HTTP/HTTPS и API.

```bash
curl -I https://example.com
curl -v https://example.com
curl -X POST -H "Content-Type: application/json" -d '{"ok":true}' https://example.com/api
```

Используется для проверки ответов, заголовков, статусов и API‑вызовов.

---

## wget

Скачивание файлов и проверка доступности.

```bash
wget -S --spider https://example.com
wget https://example.com/file.tar.gz
```

Полезен для простых проверок доступности и скачивания.

---

## mtr

Комбинация `ping` и `traceroute` с живой статистикой.

```bash
mtr 8.8.8.8
mtr -rw example.com
```

Показывает потери и задержки по каждому hop в реальном времени.

---

## tcpdump

Сниффер трафика для отладки сети.

```bash
tcpdump -i eth0
tcpdump -i eth0 port 443
tcpdump -i eth0 host 10.0.0.5
```

Частые опции:

```bash
# сохранять в pcap для Wireshark
tcpdump -i eth0 -w /tmp/capture.pcap

# без DNS/port resolve (чище вывод)
tcpdump -i eth0 -nn
```

Используется для анализа пакетов и поиска проблем в сети. Часто нужен `sudo`.

---

## nmap

Сканирование портов и сервисов.

```bash
nmap -sT -p 22,80,443 example.com
nmap -sV example.com
```

Помогает понять, какие порты открыты и какие сервисы на них работают.

---

## openssl s_client

Проверка TLS и сертификатов.

```bash
openssl s_client -connect example.com:443 -servername example.com
```

Позволяет увидеть цепочку сертификатов, параметры шифрования и ошибки TLS.

---

## iptables / nftables

Просмотр правил firewall.

```bash
iptables -L -n -v
nft list ruleset
```

## Проверка портов

### На удалённой машине

```bash
# универсально
nc -zv server.example.com 443

# альтернативы
telnet server.example.com 443
nmap -sT -p 443 server.example.com

# если это HTTP/HTTPS
curl -I https://server.example.com
```

### На своей машине

```bash
# слушающие порты
ss -tulpen
# или
netstat -tulpen

# кто слушает конкретный порт
ss -ltnp | grep 443
lsof -i :443

# проверить локально как удалённо
nc -zv 127.0.0.1 443
```

## Firewall утилиты

- **nftables** (`nft`) — современный стандарт.
- **iptables** — классика (устаревающая).
- **firewalld** — сервис‑обёртка с зонами и правилами.
- **ufw** — простой интерфейс для Debian/Ubuntu.

Примеры:

```bash
# nftables
nft list ruleset

# iptables
iptables -L -n -v

# firewalld
firewall-cmd --state
firewall-cmd --list-all

# ufw
ufw status
```

## Разница route и traceroute

- **route / ip r** показывает локальную таблицу маршрутизации (правила, куда система отправляет пакеты).
- **traceroute** показывает фактический путь пакета до удалённого узла через промежуточные маршрутизаторы.

## Шпаргалка: симптом -> утилита

- Не резолвится домен -> `dig`, `nslookup`, `getent hosts`.
- Хост не отвечает -> `ping`, `traceroute`, `mtr`.
- Порт недоступен -> `nc -zv`, `ss -ltnp`, `nmap`.
- HTTP 5xx/таймаут -> `curl -v`, `tcpdump`, логи прокси.
- Проблема TLS -> `openssl s_client`, `curl -Iv`.
- Непонятный сетевой сбой -> `tcpdump -nn` + проверка `ip r` и firewall.

## Мини-playbook для дежурства
1. L3: `ip r`, `ping`.
2. DNS: `dig +short`.
3. L4: `nc -zv host port`.
4. L7: `curl -sv`.
5. Packet level: `tcpdump`.
