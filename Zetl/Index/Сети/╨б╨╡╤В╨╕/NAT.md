
NAT (Network Address Translation) — механизм подмены IP‑адресов и/или портов на границе сетей. Чаще всего он применяется, чтобы множество внутренних устройств выходили в интернет через один публичный адрес.

---

## Зачем нужен

- Экономит публичные IPv4‑адреса.
- Упрощает схему выхода в интернет для внутренней сети.
- Позволяет публиковать внутренние сервисы через порт‑форвардинг.

---

## Основные типы

- **SNAT** — подмена исходного адреса при выходе из сети.
- **DNAT** — подмена адреса назначения при входе в сеть.
- **PAT (NAT Overload)** — подмена адреса и порта. Самый частый вариант для домашнего и корпоративного интернета.
- **Static NAT** — один внешний IP жёстко привязан к одному внутреннему.
- **CGNAT** — NAT у провайдера для экономии IPv4.

---

## Как работает (на примере исходящего трафика)

1. Клиент `192.168.1.10:54321` отправляет запрос на `1.1.1.1:443`.
2. Маршрутизатор заменяет источник на `203.0.113.5:40000` и сохраняет запись в таблице NAT.
3. Ответ приходит на `203.0.113.5:40000`.
4. Маршрутизатор по таблице NAT возвращает пакет клиенту `192.168.1.10:54321`.

NAT всегда держит **таблицу сопоставлений**, без неё ответы не вернутся корректно.

---

## DNAT и порт‑форвардинг

DNAT позволяет “пробросить” внешний адрес/порт на внутренний сервис.

Пример:

- Внешний `203.0.113.5:443` → внутренний `192.168.1.20:8443`

Это обычно используется, чтобы открыть доступ к веб‑серверу внутри сети.

---

## Hairpin NAT (loopback)

Сценарий, когда клиент внутри сети обращается к внешнему адресу своего же сервиса.

Без hairpin NAT запрос «застревает». С hairpin NAT маршрутизатор корректно возвращает трафик обратно внутрь.

---

## NAT vs firewall

- **NAT** меняет адреса и порты, но не является полноценной защитой.
- **Firewall** фильтрует трафик по правилам и состояниям.

Обычно NAT и firewall работают вместе, но это разные механизмы.

---

## Ограничения и проблемы

- Ломает прямую связность (P2P, VoIP, некоторые VPN).
- Усложняет трассировку и диагностику.
- CGNAT может блокировать входящие соединения и порты.

---

## Примеры на Linux (iptables)

SNAT (маскарадинг для выхода в интернет):

```bash
iptables -t nat -A POSTROUTING -o eth0 -j MASQUERADE
```

DNAT (проброс порта 443 на внутренний 192.168.1.20:8443):

```bash
iptables -t nat -A PREROUTING -i eth0 -p tcp --dport 443 \
  -j DNAT --to-destination 192.168.1.20:8443
```

---

## Примеры на Linux (nftables)

```bash
nft add table ip nat
nft add chain ip nat prerouting { type nat hook prerouting priority 0 \; }

nft add chain ip nat postrouting { type nat hook postrouting priority 100 \; }

# SNAT
nft add rule ip nat postrouting oif "eth0" masquerade

# DNAT
nft add rule ip nat prerouting iif "eth0" tcp dport 443 dnat to 192.168.1.20:8443
```

## Где встречается в DevOps

- Домашние и офисные маршрутизаторы.
- NAT‑gateway в облаках (AWS, GCP, Azure).
- Проброс портов на сервисы, которые не имеют публичных IP.

## On-call: сценарий -> диагностика -> fix
Нет исходящего интернета из private subnet:
```bash
ip r
curl -sv https://1.1.1.1
conntrack -L | head
```
Проверить route через NAT-gateway, таблицу NAT и лимиты conntrack.

Не работает входящий порт-форвардинг:
```bash
ss -lntp
tcpdump -ni eth0 port <port>
iptables -t nat -S | rg <port>
```
Проверить DNAT правило, backend-listen и обратный маршрут.

## Собес фокус
- Разница SNAT/DNAT/PAT и где каждый нужен.
- Почему NAT не равен firewall.
- Что ломается за NAT: P2P, входящие соединения, часть VoIP/VPN.

## Типовые ошибки
- SNAT есть, но нет FORWARD разрешения.
- DNAT настроен, но backend не слушает нужный интерфейс/порт.
- Переполнен conntrack под пиком трафика.
- Hairpin NAT не включен для внутренних клиентов.
