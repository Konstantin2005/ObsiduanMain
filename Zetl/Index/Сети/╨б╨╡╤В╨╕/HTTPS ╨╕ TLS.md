
HTTPS — это HTTP поверх TLS. TLS обеспечивает шифрование, целостность и аутентификацию сервера.

---

## Что даёт TLS

- **Шифрование** — защита содержимого от перехвата.
- **Целостность** — защита от подмены.
- **Аутентификация** — проверка сертификата сервера.

---

## Как выглядит цепочка

HTTP → TLS → TCP → IP → Ethernet

---

## Сертификаты

- Сертификат подтверждает домен и открытый ключ.
- Проверяется цепочка доверия до корневого CA.
- Обычно используются TLS 1.2 или TLS 1.3.

---

## Как проходит шифрование (упрощённо)

### 1. Рукопожатие (Handshake)

**TLS 1.3 (основной сегодня):**

1. **ClientHello** — клиент отправляет:
   - поддерживаемые версии TLS и наборы шифров;
   - случайные данные (random);
   - параметры ключевого обмена (ECDHE).
2. **ServerHello** — сервер выбирает параметры и отправляет:
   - свои случайные данные;
   - параметры ECDHE;
   - **сертификат** сервера.
3. Клиент проверяет сертификат (цепочка CA, домен, срок).
4. Обе стороны вычисляют **общий секрет** (ECDHE).
5. Из секрета выводятся **сеансовые ключи** для симметричного шифрования.

### 2. Передача данных

После рукопожатия весь HTTP‑трафик шифруется **симметрично** (AES‑GCM или ChaCha20‑Poly1305).  
Симметричное шифрование быстрое, поэтому оно используется для данных, а асимметрия — только для обмена ключами.

---

## Что шифруется, а что нет

- **Шифруется:** тело запросов/ответов, заголовки, cookies.
- **Не шифруется:** IP‑адрес, порт, часть метаданных маршрутизации.
- **SNI** может быть виден в старых версиях, в новых есть ECH (если поддерживается).

## Быстрые команды

```bash
curl -Iv https://example.com
openssl s_client -connect example.com:443 -servername example.com
```

## On-call диагностика TLS
1. Проверить срок и цепочку сертификата:
```bash
openssl s_client -connect example.com:443 -servername example.com </dev/null | openssl x509 -noout -dates -issuer -subject
```
2. Проверить negotiated protocol/cipher:
```bash
openssl s_client -connect example.com:443 -servername example.com -tls1_2 </dev/null | rg 'Protocol|Cipher'
```
3. Проверить HTTP после handshake:
```bash
curl -sv https://example.com/health
```

## Типовые ошибки
- Неполная certificate chain на сервере.
- Истекший сертификат или mismatch `CN/SAN`.
- Слишком узкий список cipher/protocol, несовместимый с клиентами.
- Отсутствие автоматической ротации сертификатов.

## Мини-лаба (15-30 минут)
1. Подними тестовый HTTPS endpoint с self-signed cert.
2. Проверь handshake через `openssl s_client`.
3. Замени cert на истекший и зафиксируй симптомы в `curl`.

## Собес фокус
- Разница между HTTPS и TLS как протоколами/слоями.
- Что именно проверяет клиент в сертификате (CN/SAN, срок, chain).
- Почему TLS 1.3 уменьшает задержки (сокращенное handshake).
