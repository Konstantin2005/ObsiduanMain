
OSI и TCP/IP — две модели описания сети.  
Коротко: **OSI** удобна для диагностики по слоям, **TCP/IP** — реальный стек интернета и продовой эксплуатации.

---

## OSI: 7 уровней и что они дают в проде

1. **Physical (L1)** — сигнал/кабель/линк.
2. **Data Link (L2)** — кадры, MAC, ARP, VLAN.
3. **Network (L3)** — IP, маршрутизация, ICMP.
4. **Transport (L4)** — TCP/UDP, порты, ретраи, порядок.
5. **Session (L5)** — управление сессией.
6. **Presentation (L6)** — формат/кодировка/шифрование (TLS).
7. **Application (L7)** — HTTP, DNS, SMTP, SSH и прикладные протоколы.

Практически для DevOps чаще работают с L2/L3/L4/L7.

---

## TCP/IP: рабочая модель интернета

Обычно используют 4 уровня:

1. **Link** (доступ к сети): Ethernet, Wi‑Fi, ARP.
2. **Internet**: IP, ICMP.
3. **Transport**: TCP, UDP.
4. **Application**: HTTP, DNS, TLS, SSH и т. д.

Есть вариант с 5 уровнями (отдельно Physical + Data Link), но суть та же: это практический стек, который реально работает в ОС, роутерах, дата-центрах и облаках.

---

## Соответствие OSI и TCP/IP

| OSI | TCP/IP | Примеры |
|---|---|---|
| L7 Application | Application | HTTP, DNS, SSH |
| L6 Presentation | Application | TLS, кодировки |
| L5 Session | Application | RPC/сессии протоколов |
| L4 Transport | Transport | TCP, UDP |
| L3 Network | Internet | IP, ICMP |
| L2 Data Link | Link | Ethernet, ARP, VLAN |
| L1 Physical | Link | кабель, оптика, радио |

---

## Инкапсуляция: как реально идёт запрос

Пример `https://site.example`:

1. L7: браузер формирует HTTP-запрос.
2. L6: TLS шифрует полезную нагрузку.
3. L4: TCP режет поток на сегменты, добавляет порты.
4. L3: IP добавляет src/dst IP и маршрут.
5. L2: Ethernet добавляет src/dst MAC.
6. L1: биты уходят по проводу/радио.

На каждом роутере **L2-заголовок меняется**, а IP/TCP полезная часть идёт дальше.

## Диагностика инцидента по слоям (runbook)

Если сервис недоступен:

1. **L7**: `curl -vk https://host` — ответ приложения/HTTP-код.
2. **L6**: `openssl s_client -connect host:443 -servername host` — TLS handshake.
3. **L4**: `nc -zv host 443`, `ss -tan` — порт/состояние TCP.
4. **L3**: `ip r`, `ping`, `traceroute` — маршрут и reachability.
5. **L2**: `ip neigh`, `tcpdump -eni <if> arp or vlan` — ARP/VLAN.
6. **L1**: `ip link`, counters интерфейса — линк/ошибки.

## Почему важно знать обе модели

- **OSI**: даёт ясную структуру для on-call и RCA.
- **TCP/IP**: объясняет, как реально ведут себя Linux, kube-networking, cloud-networking.
- На собесе правильный ответ: «для теории и локализации — OSI, для реального стека — TCP/IP».

---

## Частые ошибки

- Лечить L7-симптом, когда проблема на L3/L2.
- Игнорировать L4 и TLS при анализе «медленного HTTP».
- Путать «порт открыт» с «приложение готово обслуживать запрос».
- Делать вывод по одному инструменту без проверки соседнего слоя.
