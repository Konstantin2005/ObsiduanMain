
ARP (Address Resolution Protocol) нужен, чтобы определить **MAC‑адрес** устройства по его **IP‑адресу** внутри одной локальной сети.

---

## Зачем нужен

IP работает на L3, а доставка в локальной сети происходит по MAC на L2. Поэтому перед отправкой пакета хост должен узнать MAC адрес назначения (или шлюза).

---

## Как работает

1. Узел отправляет **ARP‑запрос** (broadcast): «Кто имеет IP X.X.X.X?»
2. Владелец IP отвечает **ARP‑ответом** (unicast): «Это мой MAC». 
3. Результат сохраняется в ARP‑кэше.

---

## ARP‑таблица

Посмотреть:

```bash
ip neigh
arp -a
```

---

## On-call диагностика ARP

Симптом: IP пингуется нестабильно, периодические потери только в одной подсети.

Проверки:
```bash
ip neigh show
arping -I <iface> <target_ip>
tcpdump -ni <iface> arp
```

Часто это:
- stale/failed записи ARP-кэша;
- конфликт IP (два узла с одним адресом);
- неверная VLAN/портовая настройка.

---

## Типовые ошибки

- Статические ARP-записи без реальной необходимости.
- Игнорирование ARP-spoofing в сегментах без защиты.
- Поиск проблемы в L7, когда фактическая проблема в L2.
