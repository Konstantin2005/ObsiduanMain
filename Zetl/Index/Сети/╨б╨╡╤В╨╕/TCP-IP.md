TCP/IP — практический сетевой стек, на котором работает интернет и большинство production-сетей.

Коротко: модель TCP/IP объясняет, как данные реально проходят от приложения до сети и обратно.

---

## Уровни TCP/IP

1. **Application** — прикладные протоколы и формат данных.
2. **Transport** — доставка между процессами (TCP/UDP, порты).
3. **Internet** — межсетевой уровень (IP, ICMP, маршрутизация).
4. **Link** — локальная доставка в сегменте сети (Ethernet, Wi‑Fi, ARP).

---

## Что делает каждый уровень

### Application

- Формирует полезную нагрузку: HTTP, DNS, SSH, SMTP, gRPC.
- Работает с именами/URL, статус-кодами, схемами API.

### Transport

- TCP: надёжная доставка, порядок, ретраи, контроль перегрузки.
- UDP: без соединения, ниже задержка, нет гарантии доставки/порядка.
- Использует порты для связи с конкретным процессом (`443`, `53`, `22`).

### Internet

- IP-адресация и маршрутизация между сетями.
- Выбор next-hop, TTL, фрагментация/PMTU.
- ICMP для служебной диагностики (echo, unreachable).

### Link

- Доставка внутри локального сегмента по MAC.
- ARP-resolve IP -> MAC.
- VLAN/тегирование и работа L2-домена.

---

## TCP/IP vs OSI

- TCP/IP — инженерно-практическая модель.
- OSI — диагностическая и учебная модель на 7 уровней.
- На собесе и в дежурстве лучше показывать обе:
  - объяснение симптома через OSI,
  - проверка/фикс через TCP/IP-инструменты.

См. подробное сопоставление: [[OSI]].

## Путь одного HTTPS-запроса

1. Приложение формирует HTTP-запрос (Application).
2. TLS шифрует (обычно относят к Application в TCP/IP).
3. TCP делает сегментацию и управление потоком (Transport).
4. IP выбирает маршрут к удалённой сети (Internet).
5. Ethernet/Wi‑Fi отправляет кадр на next-hop (Link).

Ответ проходит тот же путь в обратную сторону.

## Мини-runbook диагностики по TCP/IP

### Application
```bash
curl -vk https://example.com
dig +short example.com
```

### Transport
```bash
nc -zv example.com 443
ss -tanp | head -n 50
```

### Internet
```bash
ip route
ping -c 3 1.1.1.1
traceroute example.com
```

### Link
```bash
ip -br link
ip neigh
tcpdump -eni eth0 arp
```

## Типовые продовые проблемы

- DNS резолвит, но TCP-порт закрыт.
- TCP-порт открыт, но TLS/приложение возвращает ошибку.
- Есть маршрут «туда», но нет корректного обратного пути.
- PMTU blackhole: мелкие пакеты идут, крупные — теряются.
- Ошибки L2 (ARP/VLAN) маскируются под «приложение не отвечает».
