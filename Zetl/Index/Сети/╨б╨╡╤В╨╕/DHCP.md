
DHCP (Dynamic Host Configuration Protocol) — протокол, который автоматически выдаёт устройствам параметры сети: IP‑адрес, маску, шлюз, DNS и т. д.

---

## Зачем нужен

- Убирает ручную настройку сети на каждом устройстве.
- Позволяет быстро подключать новые устройства.
- Централизует управление адресами.

---

## Что выдаёт DHCP

- IP‑адрес.
- Маску подсети.
- Шлюз по умолчанию.
- DNS‑серверы.
- Время аренды (lease time).

---

## Как работает (DORA)

1. **Discover** — клиент ищет DHCP‑сервер (broadcast).
2. **Offer** — сервер предлагает адрес.
3. **Request** — клиент запрашивает выбранный адрес.
4. **Ack** — сервер подтверждает выдачу.

---

## Важные моменты

- DHCP работает по UDP: клиент — порт 68, сервер — порт 67.
- Если адрес занят, сервер выдаст другой.
- Адрес может быть статическим через DHCP‑резервацию (по MAC).

## On-call диагностика DHCP
Симптом: хост получил `169.254.x.x` или вообще без IP.

Проверки:
```bash
ip -br a
journalctl -u NetworkManager -n 100 --no-pager
tcpdump -ni <iface> 'port 67 or port 68'
```

Что смотреть:
- ушёл ли Discover;
- пришёл ли Offer;
- нет ли блокировки DHCP relay/firewall на сегменте.

## Типовые ошибки
- DHCP-пул исчерпан.
- Несовпадение VLAN клиента и DHCP-сервера.
- Конфликт статических адресов с DHCP-диапазоном.
- Нет резервирования для критичных узлов.

## Мини-лаба (15-30 минут)
1. Подними DHCP-сервер в тестовом сегменте.
2. Выдай адрес клиенту и проверь DORA в `tcpdump`.
3. Ограничь пул до 1 адреса и поймай симптом исчерпания.
