
Браузер — это программа, которая получает ресурсы по сети, строит из них страницу и показывает пользователю. Основные этапы: сеть → парсинг → рендеринг → взаимодействие.

---

## Основные компоненты

- **Network** — загрузка ресурсов по HTTP/HTTPS.
- **Parser** — разбор HTML и CSS.
- **JS Engine** — выполнение JavaScript.
- **Render** — построение дерева и отрисовка.
- **Storage** — кэш, cookies, localStorage, IndexedDB.

---

## Как формируется страница

1. Загружается HTML.
2. Парсер строит DOM‑дерево.
3. CSS парсится в CSSOM.
4. DOM + CSSOM → Render Tree.
5. Layout рассчитывает размеры и позиции.
6. Paint рисует пиксели.
7. Compositing объединяет слои в финальный кадр.

---

## Влияние JavaScript

- JS может блокировать парсер и рендер.
- Скрипты в `<head>` часто замедляют загрузку.
- `defer` и `async` уменьшают блокировку.

---

## Что влияет на скорость

- Количество запросов.
- Размер ресурсов.
- Время ответа сервера.
- Количество ререндеров и перерасчётов layout.

---

## Практический performance baseline

- Минимизировать критический путь рендера (critical CSS, defer/async для JS).
- Уменьшать блокирующие ресурсы в `<head>`.
- Использовать кеширование статики (`Cache-Control`, `ETag`).
- Сжимать ресурсы (gzip/br) и использовать CDN для статики.

---

## On-call диагностика «медленно в браузере»

1. Открыть DevTools -> Network:
   - проверить TTFB, размер и waterfall.
2. Открыть Performance:
   - найти long tasks, layout thrashing, script blocking.
3. Сравнить backend latency и browser rendering time.

Минимальные проверки на стороне CLI:
```bash
curl -s -o /dev/null -w 'ttfb=%{time_starttransfer} total=%{time_total}\n' https://example.com
```

Если `ttfb` нормальный, но UX медленный -> проблема чаще в фронтенд-ресурсах/рендере.

---

## Типовые ошибки

- Большой bundle JS в `<head>` без `defer`.
- Отсутствие кеш-политики для статики.
- Частые синхронные reflow/repaint при динамическом UI.
- Смешивание network latency и render latency в одном выводе.

---

## Мини-лаба (15-30 минут)

1. Возьми страницу с 5+ скриптами.
2. Переключи блокирующие скрипты на `defer`.
3. Измерь время загрузки и рендера до/после в DevTools.
4. Добавь кеш-заголовки статики и повтори замер.
