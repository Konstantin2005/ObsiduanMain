
TELNET — старый протокол удалённого доступа. Работает поверх TCP (обычно порт 23) и передаёт данные **в открытом виде**.

---

## Почему это важно

- Нет шифрования.
- Логины и пароли видны в сети.
- Используется только в учебных/лабораторных средах или в очень старых системах.

---

## Типовые сценарии

- Проверка доступности порта и простое взаимодействие по текстовым протоколам:
  - `telnet host 25` — проверить SMTP.
  - `telnet host 80` — проверить HTTP‑ответ.
- В реальных системах удалённый доступ заменяется на SSH.

---

## Быстрые примеры

```bash
telnet 192.168.1.10 23
# Проверка TCP‑порта:
telnet example.com 80
```

---

## On-call: когда Telnet еще полезен

Telnet допустим как быстрый «сырой» TCP-клиент для проверки, открыт ли порт и отвечает ли сервис текстовым протоколом.

Примеры:
- SMTP: `telnet mail.example.com 25`
- HTTP (минимальная ручная проверка):
```text
GET /health HTTP/1.1
Host: example.com

```

Для production-диагностики чаще лучше:
- `nc` для проверки порта;
- `curl` для HTTP/HTTPS;
- `openssl s_client` для TLS.

---

## Типовые ошибки

- Использовать Telnet для администрирования вместо SSH.
- Делать вывод «сервис мертв», если Telnet не подключился (причина может быть в firewall/NAT).
- Проверять HTTPS через Telnet и ожидать корректный результат без TLS.

---

## Собес фокус

- Почему Telnet небезопасен.
- Чем Telnet полезен как диагностический инструмент.
- Почему удаленный доступ в проде только через SSH.

---

## TELNET vs SSH

- TELNET: нет шифрования, небезопасен.
- SSH: шифрование, аутентификация, туннели.
