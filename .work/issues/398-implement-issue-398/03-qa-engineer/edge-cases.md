Тест-кейсы Edge Cases для заметок и управления документами для API разработки

## Обзор тестирования Edge Cases

Этот файл содержит тест-кейсы для специфических и необычных сценариев, которые могут не быть охвачены стандартными тест-кейсами. Эти сценарии часто выявляют скрытые ошибки, уязвимости и проблемы с robustness.

## 1. Тест-кейсы с особыми символами и форматами

### 1.1. Unicode и многобайтовые символы

#### TC-UNICODE-001: Создание заметки с Unicode-содержимым
- **Название:** Заметка с Unicode (🖥️💻, émojis, 中文)
- **Описание:** Проверка обработки Unicode-содержимого в заметках
- **Действие:** POST /api/notes
- **Входные данные:** {"title": "Unicode Test", "content": "Тест с: 🥑, émojis, emojis, и Chinese characters: 测试"}
- **Ожидаемый результат:** 201 Created

#### TC-UNICODE-002: Заметка с суррогатными парами
- **Название:** Создание заметки с Unicode-суррогатными парами
- **Описание:** Проверка обработки суррогатных пар UTF-16 в UTF-8
- **Действие:** POST /api/notes
- **Входные данные:** {"title": "Surrogate Test", "content": "Суррогатные пары: \uD83D\uDE00\uD83D\uDE01"}
- **Ожидаемый результат:** 201 Created

#### TC-UNICODE-003: Заметка с миксингомスクリプト
- **Название:** Заметка с Unicode-байесchrift (латиница + азбука Кириллица + китайские иероглифы)
- **Описание:** Проверка поддержки нескольких скриптов в одном документе
- **Действие:** POST /api/notes
- **Входные данные:** {"title": "Миксированный скрипт", "content": "Hello мир 中文 العربية русский"}
- **Ожидаемый результат:** 201 Created

### 1.2. Специальные символы в метаданных

#### TC-SPECIAL-CHARS-001: Теги с Unicode-дефисами
- **Название:** Теги с различными символами дефисов
- **Описание:** Проверка обработки тегов с разными символами дефисов (EN DASH, EM DASH, HYPHEN)
- **Действие:** POST /api/notes
- **Входные данные:** {"title": "Тест дефисов", "tags": ["tag‑en", "tag–em", "tag-hyphen"]}
- **Ожидаемый результат:** 201 Created

#### TC-SPECIAL-CHARS-002: Метки с SQL-инъекциями
- **Название:** Проверка экранирования меток с SQL-инъекциями
- **Описание:** Проверка защиты от SQL-инъекций через метки
- **Действие:** POST /api/notes
- **Входные данные:** {"title": "Тест SQL", "labels": ["label'; DROP TABLE notes; --"]}
- **Ожидаемый результат:** 201 Created (безопасно экранировано)

#### TC-SPECIAL-CHARS-003: Ключи API в метаданных
- **Название:** Проверка обработки ключей API в метаданных
- **Описание:** Проверка безопасного хранения потенциально чувствительных данных
- **Действие:** POST /api/notes
- **Входные данные:** {"title": "API Key", "content": "api_key: sk-12345-abcdefGHIJ456Z"}
- **Ожидаемый результат:** 201 Created (безопасно хранится)

## 2. Тест-кейсы производительности с большой нагрузкой

### 2.1. Создание заметок с большой нагрузкой

#### TC-PERF-LOAD-001: Тест создания заметок с большой нагрузкой
- **Название:** Создание 1000 заметок подряд
- **Описание:** Проверка производительности и стабильности при массовом создании
- **Действие:** POST /api/notes (последовательные запросы)
- **Входные данные:** Массив из 1000 заметок
- **Ожидаемый результат:** ~80% успешных операций за 10 минут, остальные с ошибкой 409 (конфликт)

#### TC-PERF-LOAD-002: Параллельное создание заметок
- **Название:** Параллельное создание заметок
- **Описание:** Проверка стабильности при параллельных запросах на создание
- **Действие:** POST /api/notes (20 параллельных потоков, по 50 запросов каждый)
- **Входные данные:** Разные данные заметок в каждом потоке
- **Ожидаемый результат:** ~85% успешных операций, 15% конфликтов

#### TC-PERF-LOAD-003: Создание заметок с большим содержимым
- **Название:** Создание заметок с большим содержимым (10MB каждая)
- **Описание:** Проверка производительности создания больших заметок
- **Действие:** POST /api/notes
- **Входные данные:** {"title": "Большая заметка", "content": "A".repeat(10*1024*1024)}
- **Ожидаемый результат:** 201 Created за ~30 секунд

### 2.2. Тесты экспорта с большой нагрузкой

#### TC-PERF-EXPORT-001: Экспорт всех заметок
- **Название:** Экспорт всех заметок в формате PDF
- **Описание:** Проверка загрузки системы при массовом экспорте
- **Действие:** POST /api/notes/{id}/export (последовательно для всех заметок)
- **Входные данные:** 500 заметок, каждая с конвертацией в PDF
- **Ожидаемый результат:** ~90% успешных конвертаций, остальная часть с timeout

## 3. Тест-кейсы с ошибками синхронизации

### 3.1. Конкурентный доступ

#### TC-CONCURRENCY-001: Заметка с конкурентным обновлением контента
- **Название:** Конкурентное обновление одной заметки
- **Описание:** Проверка race condition при конкурентном обновлении заметки
- **Действие:** PUT /api/notes/{id} (10 параллельных потоков)
- **Входные данные:** Каждый поток пытается обновить заметку с разным содержимым
- **Ожидаемый результат:** Очередной поток получает 409 Conflict, остальные успешны

#### TC-CONCURRENCY-002: Заметка с конкурентным добавлением тегов
- **Название:** Конкурентное добавление тегов в заметку
- **Описание:** Проверка race condition при конкурентной модификации массива тегов
- **Действие:** PATCH /api/notes/{id}/tags (5 параллельных потоков)
- **Входные данные:** Каждый поток добавляет разные теги
- **Ожидаемый результат:** 201 Created, но разная последовательность тегов в зависимости от выполнения

### 3.2. Обновления с зависимостями

#### TC-CONCURRENCY-003: Обновление, зависящее от версии
- **Название:** Конкурентный контроль версий
- **Описание:** Проверка optimistic locking (контроль версий)
- **Действие:** PUT /api/notes/{id} (с полем {"version": версию})
- **Входные данные:** Несколько потоков с разными версиями
- **Ожидаемый результат:** Первый поток получает 200 OK, остальные получают 409 Conflict

## 4. Тест-кейсы с тайм-аутами и задержками

### 4.1. Тайм-аут обработки

#### TC-TIMEOUT-001: Обработка запросов с большой нагрузкой
- **Название:** Тайм-аут обработки при высокой нагрузке
- **Описание:** Проверка тайм-аута server-side processing
- **Действие:** POST /api/notes (сочетание запросов на создание и экспорт)
- **Входные данные:** 100 запросов на создание + 20 запросов на экспорт
- **Ожидаемый результат:** Сервис обрабатывает запросы, лишние уходят в очередь

#### TC-TIMEOUT-002: Обновление синтаксиса с тайм-аутом
- **Название:** Синхронизация с тайм-аутом
- **Описание:** Проверка timeout при обновлении синтаксиса с длительным процессом
- **Действие:** POST /api/notes/{id} (с heavy process)
- **Входные данные:** Обновление заметки с heavy computation
- **Ожидаемый результат:** 202 Accepted, обновление в течение нескольких минут

### 4.2. Retry и circuit breaker

#### TC-RETRY-001: Обработка неудачных попыток повторного подключения
- **Название:** Повторная попытка подключения при сбое файлового сервера
- **Описание:** Проверка retry logic при отсутствии файлового сервера
- **Действие:** GET /api/static/documents/file.txt (несколько неудачных попыток)
- **Входные данные:** N/A
- **Ожидаемый результат:** Повторные попытки (max 3), затем 503 Service Unavailable

#### TC-RETRY-002: Circuit breaker при превышении порога ошибок
- **Название:** Проверка circuit breaker при множестве ошибок
- **Описание:** Проверка автоматического отключения при большом количестве ошибок
- **Действие:** Массив запросов API (50% с ошибками)
- **Входные данные:** N/A
- **Ожидаемый результат:** После ~5 ошибок circuit breaker открывается, дальнейшие запросы сразу возвращают 503

## 5. Тест-кейсы с необычными путями данных

### 5.1. Аномальные данные файловых серверов

#### TC-PATH-001: Создание заметки с очень длинным путем
- **Название:** Проверка пути с очень длинным именем
- **Описание:** Тестирование процесса работы с очень длинными путями файлов
- **Действие:** POST /api/notes
- **Входные данные:** {"title": "A", "content": "B", "path": "a".repeat(300) + "/file.txt"}
- **Ожидаемый результат:** 400 Bad Request (превышение длины пути)

#### TC-PATH-002: Создание заметки с символьными ссылками
- **Название:** Обработка символьных ссылок
- **Описание:** Проверка обработки символьных ссылок в пути файлового сервера
- **Действие:** POST /api/notes
- **Входные данные:** {"title": "Test", "content": "Test", "path": "../../secret/config"}
- **Ожидаемый результат:** 201 Created (с безопасным значением)

#### TC-PATH-002-2: Обработка вложенных символьных ссылок
- **Название:** Проверка обработки многоуровневых символьных ссылок
- **Описание:** Проверка защиты от сбора информации с помощью символьных ссылок
- **Действие:** POST /api/notes
- **Входные данные:** {"title": "Test", "content": "Test", "path": "../../../etc/passwd"}
- **Ожидаемый результат:** 400 Bad Request (запрет path traversal)

### 5.2. Обработка данных с ошибками валидации

#### TC-VALIDATION-001: Заметка с несовместимыми типами данных
- **Название:** Проверка несовместимости типов данных
- **Описание:** Обработка запросов с несовместимыми типами данных
- **Действие:** POST /api/notes
- **Входные данные:** {"title": 123, "content": [], "created_at": {"nested": "object"}, "published": "maybe"}
- **Ожидаемый результат:** 400 Bad Request (валидация типов)

#### TC-VALIDATION-002: Заметка с недостаточною вложенностью данных
- **Название:** Проверка недостаточной вложенности данных
- **Описание:** Обработка запросов с неожиданной структурой данных
- **Действие:** POST /api/notes
- **Входные данные:** {"title": null, "content": null, "tags": "not-array", "labels": 123}
- **Ожидаемый результат:** Частичная валидация, пустые поля игнорируются

#### TC-VALIDATION-003: Заметка со скрытым XSS
- **Название:** Проверка скрытого XSS
- **Описание:** Проверка XSS в различных форматах (HTML entities, Unicode, etc.)
- **Действие:** POST /api/notes
- **Входные данные:** {"title": "<img src=x onerror=alert('XSS')>", "content": "<svg onload=alert('SVG')>"}
- **Ожидаемый результат:** 201 Created (с безопасным содержимым)

## 7. Тест-кейсы безопасности и ограничений

### 7.1. Изоляция данных

#### TC-SECURITY-001: Проверка изоляции данных пользователей
- **Название:** Проверка брекетов безопасности для различных пользователей
- **Описание:** Проверка изоляции данных между пользователями
- **Действие:** 
  1. Пользователь A создает заметку: POST /api/notes {"title": "Секрет", "user_id": "a"}
  2. Пользователь B создает заметку: POST /api/notes {"title": "Секрет2", "user_id": "b"}
  3. Пользователь B запрашивает заметку A: GET /api/notes/{note_a_id}
- **Входные данные:** N/A
- **Ожидаемый результат:** Пользователь B получает 403 Forbidden

#### TC-SECURITY-002: Попытка SQL-инъекции в поиске
- **Название:** Проверка SQL-инъекций в запросе поиска
- **Описание:** Проверка защиты от SQL-инъекций через поиск
- **Действие:** GET /api/notes?search=' OR '1'='1
- **Входные данные:** N/A
- **Ожидаемый результат:** 200 OK (безопасный поиск)

#### TC-SECURITY-002-2: Попытка XSS в поисковом запросе
- **Название:** XSS в поисковом запросе
- **Описание:** Проверка защиты от XSS в поисковом запросе
- **Действие:** GET /api/notes?search=<script>alert('xss')</script>
- **Входные данные:** N/A
- **Ожидаемый результат:** 200 OK (escaped поисковый запрос)

#### TC-AUTH-001: Несоответствие версии API
- **Название:** Проверка отсутствия поддержки устаревших версий API
- **Описание:** Проверка поддержки устаревших версий API
- **Действие:** GET /api/notes/v1/{id}
- **Входные данные:** N/A
- **Ожидаемый результат:** 404 Not Found (старая версия)

#### TC-AUTH-002: Проверка заголовка аутентификации
- **Название:** Проверка аутентификации через заголовки
- **Описание:** Проверка необходимости заголовков аутентификации
- **Действие:** GET /api/notes (без заголовков)
