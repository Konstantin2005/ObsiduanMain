# Заметки и управление документами для API разработки

## Разработчик-ориентированный прием и обработка заметок

### Прием данных
- Ввод: текст в формате Markdown или простой текст
- Формат связи с пользователем: REST API
- Разместите в .next

### Обработка и передача данных
- Конвертация: Markdown → Notion Blocks API (обратный); также Plain Text → Notion Pages
- Поддерживаемые форматы: Markdown, Plain Text, Ollama (в пути)
- Пайплайн обработки: сортировка по форматам → выбор парсера → комбинирование → пакетная конвертация

### Требования к запоминанию
- Память: расширяемая, иерархическая, типизированная структура данных
- Кэширование: множественный тип файловых серверов, поддержка одноразовых идентификаторов
- Ручка работы: поддержка sort, filter, workspace, path
- Трансформация: багтракторы для данных, поддержка Git на файловом сервере в fsspec

### Архитектура системы
- Архитектура заметок: Deque, очередь, стек, односвязный список с множеством дополнительных полей
- API: сервис нотаций + переводчик, клиент нотаций + обновления локальной БД -> локальный API скрыт
- Эндпоинты: add-note, update-note, delete-note, get-note, search-notes, get-context, get-recent-notes, export-note, get-stats, serve-static-files, get-next-notes

### Ключевые ответы
- Метод доступа: в .next (в пути)
- Расширение API: POST /static
- Платформа: Яндекс.Таксометр
- Хранение: JS, API, файл, Notion, файловый сервер

## Основные цели задач

### Цель 1: Сервис нотаций в облаке
- Хранение и управление документами от имени пользователя
- Обновление данных из файловых серверов в унифицированном формате

### Цель 2: Локальный сервис с драйверами файлового сервера
- Обновление данных из файловых серверов (включая локальный файл)
- Обеспечение скорости и стабильности

### Цель 3: Локальный парсер и получатель
- Запуск парсера в локальном процессе
- Получение данных через HTTP
- Обеспечение скорости и стабильности

### Цель 4: Микросервис оригинального блока
- Подключение через плагин, встроенный в приложение
- Организация нестандартных синтаксисов
- Редактирование наблюдателей синтаксисов и случаев использования

## Структура системы

### Основные слои
1. **Ядро приложения**: ядро с плагинами
2. **Слой получения данных**: забирает данные из файловых серверов в необработанном виде
3. **Слой обслуживания**: обеспечивает правильный HTTP API
4. **Слой парсинга**: парсит необработанные данные
5. **Сервис передачи данных**: обеспечивает обработку и предоставление данных

### Модули работы
1. **Плагин**: чистая реализация синтаксиса
2. **Парсер**: чистая реализация парсера синтаксиса
3. **Получатель**: чистая реализация получателя данных
4. **Страница нестандартного синтаксиса**: структура страницы синтаксиса
5. **Свитч синтаксиса**: декоратор доступа к странице
6. **Обновление синтаксиса**: обновление синтаксиса через API
7. **Результат аутентификации синтаксиса**: результат аутентификации синтаксиса в Notion

### Эндпоинты API
- `/api/notes`: Работа с заметками в Notion (самые популярные)
- `/api/contexts`: Работа с контекстами в Notion
- `/api/static/{path}`: Получение статических файлов
- `/api/notes/{id}/export`: Экспорт заметок в Markdown/Plain Text/JSON
- `/api/stats`: Статистические данные
- `/api/health`: Состояние здоровья сервиса
